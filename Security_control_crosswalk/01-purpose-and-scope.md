# Purpose
A control crosswalk is a table that shows how one security control can satisfy requirements in several compliance frameworks at the same time. For example, enforcing multi-factor authentication helps meet requirements in SOC 2, ISO 27001, PCI DSS, and GDPR all at once.
Organizations that handle customer data and take card payments often face all four of these frameworks together. Building a separate set of controls for each one wastes time, money, and effort, and it creates confusion about which control belongs to which audit.
This document maps 10 common security controls across SOC 2, ISO 27001, PCI DSS, and GDPR. It is intended for security and compliance teams who want to implement each control once and reuse the same evidence across multiple audits. Each control includes a plain-English explanation, an example of audit evidence, and a short analysis of where the frameworks overlap and where they differ.

# Scope and Framework Versions
What this crosswalk covers
This document maps 10 common security controls to the relevant requirements in four frameworks. It focuses on technical and organizational security controls that appear in more than one framework.

## What is out of scope
•	Other frameworks, such as NIST CSF, HIPAA, or SOC 2 categories beyond Security (Availability, Confidentiality, and so on)
•	Every individual requirement in each framework. Only the requirements that map to the 10 selected controls are included.
•	Legal or audit advice. This is a learning project, and mappings are illustrative.
